# Prompt 29.5.0h — Strict structure context repair / confirmation relabeling

## Status

Diagnostic-only patch. No live execution, no testnet, no order submission, no risk change and no paper unlock mutation.

## Purpose

Patch 29.5.0g showed that the previous `structure_context_ok` flag was too permissive and mixed true confirmations with WAIT states and conflicts. This patch introduces a repaired semantic layer that relabels every scenario-pattern-structure row into one of five states:

- `CONFIRMATION`
- `CONTEXT`
- `WAIT`
- `CONFLICT`
- `NO_STRUCTURE`

## Added files

- `trading_bot/core/structure_context_repair.py`
- `trading_bot/run_structure_context_repair.py`
- `trading_bot/test_structure_context_repair.py`
- `data/structure_context_repair_report.json` generated by the runner

## Key rules

- `PRICE_IN_DEMAND_WAIT_CONFIRMATION`, `PRICE_IN_SUPPLY_WAIT_CONFIRMATION` and `NEAR_LIQUIDITY_WAIT_REACTION` are WAIT states, not entry confirmations.
- BUY in supply and SELL in demand are conflicts unless a directionally matching hard confirmation exists.
- Bias conflict is blocked unless directionally matching hard confirmation exists.
- True confirmation requires `confirmation_close` plus directionally matching BOS, CHOCH, MSS or retest.
- Repaired filters remain diagnostic-only.

## Safety invariant

`operational_unlock_allowed=false` in all branches. The patch does not change paper unlock settings, testnet, live execution, position limits, risk, thresholds or order flow.
